The making of / Cinder Foundry

From an instruction
to an asset.

The main purpose is to get a usable 3D object quickly from just a photo or description, so it can be viewed and tested inside a game engine. I'm developing a repeatable methodology around that journey, aiming to preserve quality while gradually using fewer tokens and costing less to run.

Read the complete workflow guide ↗︎

Where the methodology is heading

More quality from every iteration.

Fewer tokens, reusable knowledge

Keep successful recipes, concise instructions, and local validation so each asset needs less repeated explanation and fewer retries. Lower spending is a goal to measure against accepted results.

A photo or description is enough to start

The intended starting point is a single photo or short description. Optional measurements can improve accuracy; the workflow makes assumptions about scale and hidden surfaces visible.

From screen to physical prop

3D models can be prepared and exported for a slicer and 3D printer, creating physical props. A printable version needs appropriate scale, solid geometry, and sufficient thickness; these assets have not yet been checked for printing.

  1. 01

    Set the visual and technical brief

    Space-western machinery, readable silhouettes, orange and cyan energy cores, original decorative glyphs, and usable GLB exports. The brief also sets scale, pivots, materials, and animation needs.

  2. 02

    Generate a concept reference

    The built-in ImageGen tool produced the visual direction. The saved prompt specifies the shapes, materials, lighting, and camera. This image guides the modeling stage.

    Read the preserved image prompt
  3. 03

    Build geometry with Blender Python

    Skill-guided authoring creates the shapes, procedural surfaces, and named moving parts in an editable Blender scene. The delivered scripts preserve this construction process.

  4. 04

    Bake, export, and optimize

    Bake PBR material maps, export GLB, prepare smaller battlefield versions, remove redundant geometry, and rebuild tangents. Idle and activation clips stay with the assets.

  5. 05

    Inspect the actual exports

    The saved validation reports check the GLB files; renders and the Three.js gallery show those same exported models. That makes the real output visible alongside the concept.

  6. 06

    Bring the assets into Sundown

    Prepare the models at game scale, register their paths, and connect visual animation to game events. The game simulation keeps ownership of damage, movement, and objectives.

Skills and tools recorded for this collection

Discovery and pipeline guidance: find-skills, imagegen, and web-3d-asset-pipeline. The browser asset pipeline skill covers getting assets into a Three.js workflow. The saved skill lock records four Blender skills from RobLe3/cc-blender-skill.

blender-modelingblender-materialsblender-lightingblender-export

Three.js runtime guidance: three-webgl-game was also read during earlier Sundown development. It guides scenes, cameras, render loops, GLB loading, and keeping game rules outside the render objects. Its use is confirmed in the broader game work; the Foundry pack records web-3d-asset-pipeline for the asset workflow.

Execution: Blender 4.5.3 LTS, Python, glTF Transform, MikkTSpace, Khronos glTF Validator, and Three.js. The saved notes say Tripo and Gemini workflows were inspected; the final meshes were authored locally in Blender.

The exact authoring LLM/model and complete conversation were not recorded in the pack. The image prompt is preserved; the repeatable authoring instructions below are a reconstruction.

Instructions for repeating the workflow

A suggested brief based on the delivered files. This is a reusable reconstruction of the process, rather than the original conversation.

Create four original 3D game assets for Sundown at Cinder Junction:
an elemental defense tower, a support tower, a supply cache,
and a modular paving tile.

First generate a clearly labelled concept reference. Use original
designs, warm ceramic/copper/iron materials, distinct orange and
cyan energy cores, and silhouettes readable from above.

Read the modeling, materials, lighting, and export skills.
Build the assets with reproducible Blender Python scripts.
Deliver editable Blender scenes and self-contained GLBs with
ground-centered origins, named parts, PBR textures, attachment
sockets, and Idle plus Fire/Pulse animation where appropriate.

Provide detailed and battlefield versions of the towers.
Validate the final GLBs and report measured triangle counts.
Render the exported models, build a browser preview, and record
the actual tools, sources, limitations, and instructions used.
